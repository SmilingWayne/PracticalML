# 人波匹配树模型上线 Checklist

这份清单用于把骑手接波意愿模型接入线上算法包前的自查。重点不是“模型能不能训练”，而是“这个分数在线上是否可信、可解释、可回滚”。

## 1. 样本与标签

- [ ] 一行样本定义清楚：`request_time, wave_id, rider_id, recommend_id` 是否唯一。
- [ ] 正样本定义清楚：骑手接受该波次、接受该推荐、还是接受推荐中的任意波次。
- [ ] 负样本定义清楚：主动拒绝、超时未响应、被别人抢走、未曝光候选是否区分。
- [ ] 一次推荐多个波次时，未被点击/未被接的波次是否作为负样本有明确规则。
- [ ] 抢波导致的“没机会接”没有被简单当成强负样本。
- [ ] 训练集、验证集、测试集按时间切分，且测试集时间晚于训练集。
- [ ] 样本权重策略明确，例如高峰餐段、核心商圈、稀缺骑手是否加权。

## 2. 特征口径

- [ ] 特征列表有版本号，包含名称、类型、单位、默认值、取值范围和 owner。
- [ ] 所有聚合特征都有时间 cutoff，例如 `rider_aoi_accept_rate_7d` 只使用推荐时刻之前的数据。
- [ ] 离线 Hive SQL 和在线特征服务使用同一口径，或有自动校验。
- [ ] 距离、时长、顺路度、承托比等核心特征的单位在线离线一致。
- [ ] 类别特征的未知值、空值、低频值处理方式一致。
- [ ] 缺失值不是随意填 0；0、空、未知、无历史这几种语义被区分。
- [ ] 新增特征经过泄漏检查，尤其是包含“最终结果”“未来单量”“最终成团”的字段。

## 3. 训练流程

- [ ] 训练脚本固定随机种子，并记录训练数据时间窗。
- [ ] 训练输出包括模型文件、特征 schema、参数、指标、训练代码版本和数据版本。
- [ ] 使用时间切分验证，而不是只用随机交叉验证。
- [ ] 指标至少包含 AUC、PR-AUC、LogLoss 或 Brier Score、分桶校准。
- [ ] 对关键餐段、城市、商圈、供需状态分组评估。
- [ ] 和当前启发式打分做 baseline 对比，而不是只看模型自身指标。
- [ ] 重要特征通过 Gain、Permutation Importance、SHAP 交叉验证。
- [ ] 排查异常高重要性特征，确认不是泄漏或 ID 记忆。

## 4. 模型文件与推理

- [ ] XGBoost 使用 `.json` 或 `.ubj`；LightGBM 使用 text booster；CatBoost 使用 `.cbm`。
- [ ] 模型加载后做固定样本推理校验，确认离线和线上输出一致。
- [ ] 线上输入特征顺序和训练 schema 强校验，不允许静默错位。
- [ ] 推理超时有降级策略，例如回退旧模型或启发式分数。
- [ ] 模型版本、feature version、score 被写入日志。
- [ ] 每次推理记录候选集大小和过滤原因，便于解释召回/排序损失。
- [ ] 分数范围和异常值有监控，例如全 0、全 1、分布突然漂移。

## 5. 策略接入

- [ ] 模型输出被定义为“接波概率/偏好分”，不是最终派发决策。
- [ ] 策略层仍然处理业务硬约束：距离上限、骑手状态、波次承托比、风险控制、黑白名单。
- [ ] KM/排序/组合策略明确如何融合模型分、业务分和供需分。
- [ ] 低分过滤阈值经过回放验证，避免误杀长尾可接受波次。
- [ ] 一次推荐多个波次时，分数组合方式明确，例如 top-N、diversity、波次互斥。
- [ ] 抢波风险有处理，例如同一波次派给多个骑手时的并发上限。
- [ ] 推荐顺序或展示位置被记录，因为它会影响骑手选择。

## 6. 校准与解释

- [ ] 如果下游把分数当概率使用，使用独立验证集做 Platt 或 Isotonic 校准。
- [ ] 校准前后都看 reliability curve 和分桶实际接起率。
- [ ] 对高分低接、低分高接样本做 case study。
- [ ] 每个模型版本保留全局 SHAP 或特征重要性报告。
- [ ] 能解释单条推荐为何高分：例如顺路度高、AOI 熟悉、距离短。
- [ ] 解释报告避免把 SHAP 当因果结论，只说明模型使用了哪些信号。

## 7. 在线实验与监控

- [ ] 先做 shadow 或小流量灰度，确认推理延迟和分数分布。
- [ ] A/B 实验主指标明确：推荐接受率、波次接起率、成交单量、骑手打扰率。
- [ ] 保护指标明确：超时率、取消率、骑手投诉、商家等待、低供给区域覆盖。
- [ ] 指标分餐段、城市、商圈、天气、供需状态观察。
- [ ] 监控模型输入特征 PSI/KS 或分位数漂移。
- [ ] 监控线上分数分桶的实际接起率，发现校准漂移。
- [ ] 有一键回滚旧模型或关闭模型分的开关。

## 8. 回流与迭代

- [ ] 线上日志能还原每次推荐的候选集、特征、分数、排序、最终展示和骑手反馈。
- [ ] 新训练数据优先使用线上真实打分日志，减少训练-推理偏差。
- [ ] 定期对未展示候选做采样探索，否则模型只学习旧策略展示过的空间。
- [ ] 重训频率有依据，例如按周重训或按漂移触发。
- [ ] 每次重训都有固定回放集，防止模型在历史关键场景退化。
- [ ] 保留失败案例库，例如高峰餐段、高波多人少、抢波冲突、熟悉 AOI 失效。

## 9. 最小上线包

一个能安全接入线上算法包的最小包至少包含：

- 模型文件：`model.json` / `model.txt` / `model.cbm`。
- 特征 schema：字段名、顺序、类型、默认值、单位。
- 预处理对象：编码器、缺失值规则、截断规则。
- 模型配置：超参、训练窗口、label 定义、样本过滤规则。
- 离线评估：整体和分组指标、校准曲线、重要性报告。
- 线上配置：流量比例、降级开关、阈值、版本号。
- 监控面板：延迟、异常率、分数分布、核心业务指标、保护指标。
